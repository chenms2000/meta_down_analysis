## 论文正文版本

### 可选分析插件：基于知识图谱的代谢组结果解释与证据回链

为便于读者对代谢算法输出进行进一步生物学解释，本研究同时提供一个可选的分析插件。该插件不参与主算法的训练、参数优化或核心性能评价，而是作为一个独立的后处理模块，对用户输入的代谢物列表或差异代谢表进行实体规范化、知识图谱传播、通路/靶点/疾病候选排序和文献证据回链。读者可根据研究目的选择是否运行该模块；未运行该模块不影响本文主算法结果的复现。

插件以冻结版本的代谢知识图谱为分析背景。知识图谱由公开数据库、规范化实体表、代谢物-反应-基因/蛋白-通路-疾病/靶点关系以及句级文献证据组成。当前实现支持以 CSV、TSV、TXT 或 JSON 形式输入代谢物名称、HMDB、ChEBI、PubChem CID、KEGG、InChIKey、分子式、m/z、保留时间、MS/MS 特征，以及可选的差异信息，例如 log2 fold change、P 值、校正 P 值和变化方向。插件首先对输入进行质量检查和实体解析。只有满足匹配分数和候选间隔要求的代谢物进入后续评分；歧义或未匹配条目被保留在复核队列中，不会被强制纳入图传播。

在分析阶段，插件将匹配成功的代谢物转换为种子节点，并结合差异方向和显著性生成种子权重。随后在类型约束的异构知识图谱上进行传播，并结合直接通路富集、文献支持和解释路径代价生成通路、靶点和疾病候选排序。图传播采用固定参数和冻结 release，形式为：

\[
\pi=(1-\alpha)y+\alpha W\pi
\]

其中 \(y\) 为由输入代谢物构成的种子向量，\(W\) 为经过边类型约束和归一化后的转移矩阵，\(\pi\) 为传播后的节点得分。解释路径以边置信度的负对数和作为路径代价：

\[
C(path)=\sum_{e \in path}-\log(p_{final}(e))
\]

插件输出结构化的 `analysis_pack`，包括输入检查摘要、已匹配/歧义/未匹配条目、通路排序、靶点排序、疾病排序、解释路径、文献证据包、质量警告、引用到的图边和句级证据，以及用于复现的输入哈希、配置哈希、release ID 和结果哈希。所有排序条目均要求至少回链到图边、来源记录或文献证据；缺少证据回链的结果不会被作为有效解释输出。

该插件的定位是研究辅助和假设生成，而非临床决策支持。文献抽取结果作为证据 overlay 使用，可增强或标记候选解释，但不会自动改写规范图谱事实。可选的语言模型解释层仅用于把结构化结果改写为带来源引用的自然语言说明，不参与实体解析、打分、图谱写入或事实创建；若解释文本未能通过本地证据绑定检查，则结果被拦截。由插件得到的靶点、疾病或药物相关结果应理解为可复核的研究优先级线索，而不是因果证明或治疗建议。

## 具体流程说明

### 1. 插件输入

插件接受两类主要输入：

1. 代谢物列表：仅包含代谢物名称或数据库 ID，适合快速探索通路覆盖情况。
2. 差异代谢表：包含代谢物标识、log2FC、P 值、FDR/Padj 和方向信息，适合生成方向性解释和候选机制排序。

推荐字段如下：

| 字段类型 | 示例列名 | 用途 |
|---|---|---|
| 代谢物名称 | `name`, `metabolite`, `compound` | 按名称或同义词解析代谢物 |
| 外部 ID | `HMDB`, `ChEBI`, `PubChem CID`, `KEGG`, `InChIKey` | 提高实体规范化稳定性 |
| 谱学特征 | `formula`, `mz`, `adduct`, `rt`, `ms2_peaks` | 辅助区分同名、同分异构或质量相近化合物 |
| 差异信息 | `log2FC`, `pvalue`, `padj`, `direction` | 生成方向和显著性相关的种子权重 |
| 可选背景 | `cancer_type`, `tissue`, `cell_type`, `cell_line` | 对上下文相关 overlay 进行软加权或硬筛选 |

### 2. 数据和 release 构建

插件以冻结 release 为单位运行。每个 release 包含以下层次：

1. `raw_lake`：保存原始来源文件、下载时间、许可层级和 checksum。
2. `normalized_store`：保存规范化实体、交叉引用、来源记录和基础关系。
3. `graph_projection`：将规范化表投影为分析用异构图，包含节点、边、边类型和解析索引。
4. `compound_match_index`：建立代谢物匹配索引，包括名称、外部 ID、InChIKey、分子式/质量、RT 和 MS/MS 辅助索引。
5. `literature_evidence`：从本地文献语料生成句级实体提及、候选关系和边支持证据。

当前示例 release 为 `mvp_20260513T002254`。该 release 的图投影包含 853,614 个节点和 5,057,418 条边；代谢物解析索引包含名称、外部 ID、结构和质量相关索引；文献证据层扫描 50,035 篇文章，生成 898,114 个句级提及、52,277 个候选关系和 32,555 条文献边支持记录。这些数字仅用于说明当前实现规模，最终论文中应替换为正式发布版本的统计量。

### 3. 实体解析与输入质控

对每条输入记录，插件按以下信息生成候选代谢物：

1. 外部 ID 精确匹配，例如 HMDB、ChEBI、PubChem CID、KEGG。
2. InChIKey 或结构骨架匹配。
3. 名称、同义词和常见生化名称匹配。
4. 分子式、精确质量、m/z 和加合物匹配。
5. 可选 RT 和 MS/MS 特征匹配。

候选按匹配分数组合排序。当前实现默认要求 top1 分数不低于 60，且 top1 与 top2 的分差不低于 15，才将输入判定为已匹配。未达阈值的条目进入歧义队列；没有候选的条目进入未匹配队列。歧义和未匹配条目会出现在输出报告中供人工复核，但不会静默进入图评分。

### 4. 种子权重与图传播

已匹配代谢物被映射为图中的种子节点。若输入提供 log2FC、P 值或 Padj，插件会将差异强度、显著性和方向一致性纳入种子权重；若输入仅为代谢物列表，则以列表模式运行，并在质量警告中标记缺少差异信息。

随后插件在类型约束图上执行传播。允许的高优先级路径包括代谢物到通路、代谢物到反应、代谢物到基因/靶点、以及进一步到疾病或表型的关系。为了避免高度连接节点主导结果，传播图使用类型 beam 压缩和度惩罚，并在输出中记录压缩信息和可能的质量警告。

### 5. 排序与解释路径

插件生成三类主要排序：

1. 通路排序：结合输入代谢物覆盖、富集信号、传播分数和文献增强。
2. 靶点排序：主要来自图传播、代谢物-基因/靶点关系和证据支持。
3. 疾病排序：主要来自代谢物、通路、靶点与疾病/表型之间的图连接和文献支持。

每个候选条目均保留 `score_components`，并附带 `claim_refs` 与 `evidence_refs`。解释路径记录从输入代谢物到终端通路、靶点或疾病节点的节点序列、边序列、路径置信度和证据引用。路径得分越高、代价越低，表示该解释越容易被当前冻结图谱和证据层支持。

### 6. 文献证据 overlay

文献层从本地文章集合中抽取实体提及和候选关系，并将其映射到图边或候选解释。证据类型包括：

| 类型 | 含义 |
|---|---|
| `confirm` | 文献支持既有图谱边 |
| `support_direction` | 文献支持方向性解释 |
| `novel_candidate` | 文献提示潜在新关系，但未进入规范图谱事实 |
| `conflict_candidate` | 文献提示与已有方向或关系存在冲突 |
| `unresolved` | 证据不足或实体/关系未能可靠解析 |

文献证据只作为 overlay：它可以提高既有关系的解释权重，也可以提示潜在假设，但不会自动创建规范图谱事实。需要人工复核后，才能将新的关系纳入后续 release。

### 7. 可选自然语言解释层

插件可调用本地模板或外部语言模型生成自然语言摘要，但该层被设计为“叙述器”而不是“判断器”。解释层只能读取冻结的 `analysis_pack`、证据包、子图和 release 元数据；不能读取解析器内部状态，不能修改分数，不能写入图谱，也不能创建新事实。每个自然语言声明必须绑定到结构化输入中的来源引用。若输出中出现未被来源支持的因果、分数、实体解析或图谱修改声明，本地 guard 会阻断该解释。

### 8. 输出与复现

插件的核心输出为 `analysis_pack.v1`，主要字段包括：

| 字段 | 内容 |
|---|---|
| `input_summary` | 输入数量、匹配数量、歧义数量、未匹配数量、种子权重摘要 |
| `matched` | 成功解析的输入记录和候选信息 |
| `ambiguous` | 因置信度或候选间隔不足而暂停评分的记录 |
| `unmatched` | 未能映射到当前 release 的记录 |
| `quality_warnings` | 输入、解析、传播和证据相关警告 |
| `pathway_rankings` | 通路候选排序及证据回链 |
| `target_rankings` | 靶点候选排序及证据回链 |
| `disease_rankings` | 疾病/表型候选排序及证据回链 |
| `top_explanation_paths` | 主要解释路径 |
| `literature_evidence_pack` | 文献支持数量、PMID/PMCID、句级证据和支持类别 |
| `evidence_refs` | 所有被引用的图边、来源记录和文献证据 |
| `determinism` | 输入哈希、release ID、配置哈希、合同哈希和结果哈希 |
| `blocked_reasons` | 阻止评分或解释的原因 |

在相同输入、相同 release 和相同配置下，插件应返回相同的结果哈希。论文复现时应报告 release ID、配置版本、输入文件、分析命令和输出哈希。

### 9. GitHub 发布建议

若将插件发布到 GitHub，建议将其明确标注为“optional analysis plugin”或“research-use plugin”，并在 README 中包含以下内容：

1. 插件不属于主算法必要步骤，主论文结果不依赖用户运行该插件。
2. 插件用途为代谢组结果解释、证据回链和研究优先级排序，不用于临床诊断或治疗决策。
3. 所有数据源、许可、版本、下载日期和 checksum 应通过 manifest 记录。
4. 示例数据、最小 release 或可下载 release 包应与代码分离，避免把受许可限制的数据直接提交到仓库。
5. 提供最小运行命令、输入模板、输出 JSON schema、验证命令和已知限制。
6. 在 release 页面固定版本号，例如 `v0.1.0`，并在论文中引用对应 tag、commit hash 或 Zenodo DOI。

论文中可写为：

“The optional analysis plugin, source code, input templates, output schema, and reproducibility scripts will be released at [GitHub URL] under version [tag/commit]. The plugin is not required for reproducing the core algorithmic results; it is provided as a research-oriented interpretation layer for readers who wish to inspect pathway, target, disease, and literature-evidence links derived from their own metabolite tables.”
